# Theme Studio conventions

- Project slug: `heroui-theme-studio`. Public name: **HeroUI Theme Studio**. Descriptor: **Unofficial theme generator for HeroUI v3**. Keep the name and descriptor consistent across the header, search and social metadata, and README.

## Theme and components

- Target **HeroUI React v3** and **Tailwind CSS v4** in the web editor and catalog. Use v3 compound components and supported props. The phone viewer runs `heroui-native` components through Expo Web in `src/features/native/runtime`.
- Global theme is owned by `ThemeStudioProvider` and `useThemeEditor`; CSS custom properties are applied to document.documentElement so popovers/portals also inherit them.
- Local component example states stay inside their own `features/playground/examples/*Playground.tsx` and must not write to the global ThemeConfig or localStorage.
- Keep catalog token guides in `features/playground/inspection/`. Each guide combines the component’s stylesheet references with verified part-level mappings when available. The **Tokens** panel can focus the matching editor control. Treat missing direct references as incomplete evidence about inherited styles.
- Reuse `ComponentPlayground`, `PlaygroundControls`, `PlaygroundPreview`, `ControlSelect` and `ControlSwitch` where appropriate. Group only tightly related OSS components in each example file; no fake component API. Generic `cloneElement` prop injection is discouraged: v3 components have different capabilities and composition.
- Default colors match installed @heroui/styles 3.2.7 in packages/styles/themes/default/variables.css, including hue, chroma, precision and safe var(--...) aliases. Never force a shared neutral hue onto native tokens. HeroUI ColorPicker emits HEX, not OKLCH; original CSS values are preserved until edits. Persisted legacy custom edits must survive default migrations.
- **User-supplied CSS is the definitive editing contract**: exactly the 31 `COLOR_TOKENS` in `model.ts`, plus `--radius`, `--field-radius` and `--font-sans`. Do not reintroduce font-size/line-height/border-width/disabled-opacity/ring-offset controls or nonstandard theme tokens.
- Add new global settings to model, storage validation, document application, CSS export and tests.
- Paste/import HeroUI CSS through `import-css.ts` only: parse named light/dark blocks and whitelist CSS variables, never inject arbitrary CSS. Preserve per-mode radius/field radius/font via optional `modeSettings`, and migrate them through local storage/export.
- WebLLM must load **only on explicit user action**, in its own Worker. Never require an API key or invoke a paid remote model silently.
- Never apply AI output directly as CSS or arbitrary JS. Whitelist parsed tokens and bounded values; apply only after user approval.
- Keep keyboard access, visible focus, mobile responsive styles, and reduced motion.
- Color editor tiles: use HeroUI ColorPicker.Trigger/Popover, ColorSwatch, ColorArea and ColorSlider; exactly two columns per token group, with CSS variable names on the tiles. The popover includes a shuffle action and a HeroUI ColorField for HEX, with no preset swatches or arbitrary CSS input. Show the Alpha slider only for field-border, preserve alpha while editing RGB, and keep the Theme Builder and library theme presets. Do not set a fixed inner popover width: HeroUI uses its own min-width. Keep controlled Color objects in HSB during editing and avoid live recoloring of the popover when changing --overlay.
## Theme assistant

- The AI lives in a right-hand conversational panel opened from the header. Keep it mounted while hidden to preserve chat messages and the downloaded model. Never place it before the showcase in main content.
- WebLLM's `response_format: {type:'json_object'}` **requires** a serialized string `schema` in this version. Always build requests through `buildThemeRequest`, never inline a schema-less response format.
- Keep the latest proposal available as context for conversational revisions. Never auto-apply generated values.

- Theme AI is **not fine-tuned**; ensure domain-restriction stays in `intent.ts`, reinforced by `prompt.ts`, and all outputs are whitelisted and validated.
- Do not ask small LLMs to invent every semantic token: use compact `schema.ts` seeds and derive coherent palettes via `palette.ts`. Explicit user color requirements take precedence over model-generated defaults.
- Manage strongest-first local WebLLM model priorities only in `config.ts`. Filter by the shipped `prebuiltAppConfig.model_list` and WebGPU features, then transparently fall back on failure. Never introduce a manual model selector unless requested.
- Loading affordance in the chat is one spinner and one short status text, not a percentage/progress card.

- WebLLM/Qwen3.5 may return `<think>...</think>` before JSON despite `enable_thinking: false`; always parse via `extractThemeJson` in `response.ts`, which must never accept reasoning-only JSON. On malformed/incomplete output, call `generateThemeWithRecovery` to retry on the **same** engine before model fallback. Keep regression tests for think tags, JSON truncation, escaped strings and retry requests.

- Differentiate **new theme requests** from refinements via `direction.ts`. Never attach previous-theme colors to a new brand/style request. Named design inspirations live in curated `style-references.ts` with verified colors; users' explicit accent requests take precedence. Test scenario: previously violet -> new Spotify must render green #1ED760 on charcoal #121212, while 'más contraste' should preserve prior hue.

## Previews and styling

- Web previews are `?view=components` and `?view=collage` (shared `ComponentGallery`), plus `?view=website` (original compositions using free React components). The platform switch opens `?view=native` (`NativePreviewPage`). All previews share the theme; export CSS using the selected platform's format.
- Never import, mimic or market **HeroUI Pro** charts, KPI cards, DataGrid, commercial templates, or Pro-only components. Use only verified components exported from the installed free `@heroui/react`; style the website's layout normally without presenting its HTML as library components.
- The current public catalog component inventory comes from https://heroui.com/en/docs/react/components; verify changing APIs against docs and TypeScript. Each demo's local controls must match real component props.
- Keep `ComponentGallery.test.ts` aligned with the official free React catalog. The current inventory covers 73 components.
- Use container queries in the website demo so it responds when the AI panel reduces its available width.

- **Strict CSS rule:** `src/app/styles.css` must contain *only* `@import "tailwindcss";` and `@import "@heroui/styles";`. All app-owned wrappers/layout/typography belong in Tailwind utility classes in JSX; **never write CSS rules, @apply, or global selectors** overriding HeroUI BEM/component slots. Never add visual Tailwind styles to HeroUI components; use their native props and own wrappers for layout.
- Keep the `src/app/styles.test.ts` guard green to prevent future accidental component CSS overrides.


- The `default` preset is shipped @heroui/styles 3.2.7 native CSS; the `heroui-builder` preset intentionally reproduces the user-provided official Theme Builder Default export (all 31 light/dark tokens). Neither supersedes the other. The Builder template shares the old exact-color snapshot in `legacy-default.ts`; do not merge or approximate these distinct palettes.

## Architecture and verification

- `src/main.tsx` boots the Vite/React app. `src/app/` owns the shell, `?view=` navigation, platform switching and dialogs. Each screen loads on entry. `components` and `collage` share one gallery module, `website` owns its local demo data, and `native` loads the separately built Expo Web iframe when selected.
- Put feature UI under `src/features/<feature>/`, next to its state and tests. Keep React-free operations in `kebab-case` modules such as `import-css.ts`. Use `PascalCase.tsx` for components, `useX` for hooks with React behavior, and local relative imports. Use `src/components/` for UI that has no feature dependencies. Extract a hook when it owns a distinct stateful behavior. Share pure transformations directly and keep imports from domain modules independent of UI.
- `theme/storage.ts` owns preference persistence and legacy reads. `theme/conversion.ts` prepares the same approved values for the root document, the Native bridge and CSS export. Keep color drags in the animation-frame preview path and persist committed edits. Keep theme data out of sample and composition state.
